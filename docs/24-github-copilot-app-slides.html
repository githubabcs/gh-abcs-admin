Executive Briefing

The GitHub Copilot App

The agent-native desktop experience — one control center to direct a fleet of AI agents from idea to merge, across your connected repositories.

The idea in one line
If the IDE is where you write code with an assistant, the Copilot app is where you direct & verify a fleet of agents that do the work.

idea → issue → plan → pull request → merge — from a single desktop control center.

What it is

One control center. Everything in one place.

🗂️

My Work

Every active session, issue, PR, and automation across your connected repos — one view that tells you what needs attention next.

⛓️

Parallel, isolated sessions

Each new-working-tree or cloud session works on its own branch — avoids working-tree collisions, no branch juggling.

🎛️

An autonomy dial

Interactive, Plan, or Autopilot — you decide how much the agent does on its own, and change it any time.

🔗

Native to GitHub

Repos, branches, issues, PRs, and CI work out of the box. No plumbing, no extra setup.

The problem it removes

Agent work today is scattered and unverifiable.

  • Context scatters across windows and tools
  • You lose track of what's actually running
  • Code lands in PRs without a clear trail of what the agent tried or validated
  • Too much time lost reviewing and context-switching
🧭

The app's answer

Make every agent's intent visible, steerable, and reviewable — isolated workspaces, shared surfaces to inspect work, and a clear path to merge. "Agent autonomy stays bounded by what teams can verify."

Canvases — a shared surface for humans and agents

Instead of burying work in a chat thread, a canvas lets you see, edit, and verify what the agent is doing — in context, in real time.

Work that runs itself

Automations & Agent Merge

⏰

Automations

Save recurring tasks to run on a schedule, on demand, or when an issue is created. Cloud automations run even when your machine is off — with only the tools you grant.

Daily issue triageMorning PR sweep
✅

Agent Merge

Carries a PR through review, checks, and merge conditions — monitors CI, addresses failing checks, waits for reviewers. You choose how far it goes.

Green-to-merge

Unattended work is bounded by the tools you preauthorize — grant least privilege. Cloud runs consume AI credits and Actions minutes.

Bounded by design

Isolation & safety, so agents stay reviewable

🌳

Worktrees

Each new-working-tree session on its own branch copy — avoids working-tree collisions between parallel agents.

Not a security boundary
📦

Sandboxes

A bounded place to run code — cloud sandbox in the app (GitHub-hosted Linux on Azure); local sandbox via the Copilot CLI.

Cloud (app) · local (CLI) · Preview
🛡️

Policy & review gates

Scoped tools, MDM/Intune policy, admin gating, and human review gates for defense in depth.

Governed

Honest framing: a worktree is not a security boundary — pair it with sandboxes, scoped credentials, and review gates. These reduce risk; they don't eliminate it.

Availability & governance

Works with any plan — governed for the enterprise

🎟️

Any Copilot plan — or none

Free, Pro, Pro+, Business, Enterprise — or bring your own key with no plan. The base app works with any plan; individual features may need entitlements/policies.

🏛️

Admin & trust controls

Business/Enterprise enable the Copilot CLI policy; cloud automations require the cloud-agent policy and org allow-listing. Local sandbox policy via Intune/MDM.

Preview  Announced at Build 2026 and evolving fast. Trust review before rollout: public-code-matching policy, data handling, and telemetry — and verify plans, policies, and feature availability against live docs.
